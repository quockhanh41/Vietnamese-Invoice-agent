# M5-C FastAPI Implementation Note

**Date**: 2026-08-01  
**Milestone**: M5-C (The HTTP API)

## 1. Executive Summary

M5-C delivers the HTTP surface for the Vietnamese Invoice & Expense Agent, exposing liveness, invoice listing & inspection, aggregate reporting, human-in-the-loop decision resolution, and asynchronous batch processing over FastAPI.

The implementation strictly maintains the "Ledger Has One Door" principle introduced in M5-A: the HTTP API adds no secondary write path to `journal_entries`, does not import `tools.guards` or the journal repository, and forces all human approval decisions through `approval.submit_decision`.

## 3. Department Field Consequence Analysis

The `department` form field on `POST /batches` is optional (`Form(default=None)`).

### Structural Consequence of Omission
- `serial_join` groups budgets by the department declared on the **task input** (`item["department"]`).
- Raw `InvoiceData` parsed from vendor XML/PDF carries no department (as classification outputs category/department onto invoice records during graph processing, but budget reconciliation routes against the task-declared department).
- Therefore, uploading a batch without specifying `department` persists invoices and allows posting if clean, but invoices land in `unroutable` state during budget checks and are **never reconciled against department budget limits**.
- This behaviour is deliberate (consistent with M4-D's removal of arbitrary default budget limits): the system refuses to silently invent a budget department for unassigned uploads.

## 4. Money Serialization & API Schema Design

- **Monetary Serialization**: All financial figures (`amount_limit`, `consumed`, `remaining`, `total_amount`, etc.) are stringified at source in `db/queries.py` or via the `_jsonable` boundary formatter. JSON numeric floats lose precision on 64-bit IEEE 754 representations (e.g. `21618409.09000000` in real fixtures).
- **Security Boundary**: `DecisionRequest` explicitly excludes `posting_authority`, `approval_id`, `status`, or `entry_id`. With `extra="forbid"`, clients cannot tamper with ledger authority fields over HTTP.
