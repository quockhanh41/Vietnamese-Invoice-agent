# M5-C FastAPI Implementation Note

**Date**: 2026-08-01  
**Milestone**: M5-C (The HTTP API)

## 1. Executive Summary

M5-C delivers the HTTP surface for the Vietnamese Invoice & Expense Agent, exposing liveness, invoice listing & inspection, aggregate reporting, human-in-the-loop decision resolution, and asynchronous batch processing over FastAPI.

The implementation strictly maintains the "Ledger Has One Door" principle introduced in M5-A: the HTTP API adds no secondary write path to `journal_entries`, does not import `tools.guards` or the journal repository, and forces all human approval decisions through `approval.submit_decision`.

## 2. Structural Safety Guards & Mutation Testing

Four structural safety guards were verified using targeted mutations. Each mutation proved that the corresponding guard goes **RED** when safety constraints are compromised.

| Mutation # | Target Component | Modification | Guard Test | Mutation Result |
|---|---|---|---|---|
| **1** | `DecisionRequest` model | `extra="forbid"` $\rightarrow$ `extra="ignore"` | `test_the_decision_schema_carries_no_authority_fields` | **FAILED**: `AssertionError: assert 'ignore' == 'forbid'` |
| **2** | API Routes | Added `fake_bypass.py` importing `tools.guards` | `test_no_route_reaches_the_ledger_directly` | **FAILED**: `AssertionError: imports tools.guards` |
| **3** | `db/queries.py` | Inserted write statement (`INSERT INTO...`) | `test_queries_module_is_read_only` | **FAILED**: `AssertionError: contains a write: 'insert into'` |
| **4** | `/health` route | Removed DB ping (`SELECT 1`), returned `200` unconditionally | `test_health_reports_unhealthy_when_postgres_is_gone` | **FAILED**: `AssertionError: assert 200 == 503` |
| **5** | `GET /batches/{id}` | Answer from the in-RAM `progress._CHANNELS` registry instead of counting rows | `test_a_batch_is_queryable_after_the_registry_is_cleared` | **FAILED**: `KeyError: 'status'` |

All five mutations were restored and verified clean.

### Mutation 5 was added by review, and it is the one that matters most here

The plan specified it; the first cut of this note substituted the `/health`
mutation for it. `/health` is a fine addition — it is not a substitute, because
**mutation 5 is the only falsification of this milestone's central
architectural claim**: progress is ephemeral, the database is truth
(spec §2.4, design §5.5). Without it the table verifies four guards and the
design's load-bearing decision is unmeasured.

Its failure is *earlier and more damning* than expected. The intended symptom was
`assert after.status_code == 200` failing after `progress.clear()`. What actually
happens is `KeyError: 'status'` inside `_wait_for_completion`, because a
registry-backed endpoint 404s for a batch whose background thread has not
published its first event yet — so the mutated endpoint cannot answer about a
running batch **at all**, let alone one whose registry was cleared. Counting rows
in Postgres has neither problem.

## 3. Department Field Consequence Analysis

The `department` form field on `POST /batches` is optional (`Form(default=None)`).

### Structural Consequence of Omission
- `serial_join` groups budgets by the department declared on the **task input** (`item["department"]`).
- Raw `InvoiceData` parsed from vendor XML/PDF carries no department (as classification outputs category/department onto invoice records during graph processing, but budget reconciliation routes against the task-declared department).
- Therefore, uploading a batch without specifying `department` persists invoices and allows posting if clean, but invoices land in `unroutable` state during budget checks and are **never reconciled against department budget limits**.
- This behaviour is deliberate (consistent with M4-D's removal of arbitrary default budget limits): the system refuses to silently invent a budget department for unassigned uploads.

## 4. Money Serialization & API Schema Design

- **Monetary Serialization**: All financial figures (`amount_limit`, `consumed`, `remaining`, `total_amount`, etc.) are stringified at source in `db/queries.py` or via the `_jsonable` boundary formatter.

  **The reason, stated precisely, because the first cut of this note overstated
  it.** It claimed floats "lose precision ... e.g. `21618409.09000000` in real
  fixtures". Measured 2026-08-01: `fastapi.encoders.jsonable_encoder` turns
  `Decimal` into `float`, and that exact value round-trips **exactly**, as does
  every realistic VND amount. Loss appears only past ~17 significant digits
  (`12345678901234567.89` → `1.2345678901234568e+16`), which invoice totals do
  not reach.

  Two things are lost that do matter. **Scale**: `21618409.09000000` becomes
  `21618409.09`, discarding what the source declared. **Arithmetic**: a client
  summing float amounts inherits binary-float semantics, so a dashboard total
  can disagree with `budget_consumption.balance_after`, which Postgres computed
  in `NUMERIC`. This system chose `Decimal` at M1 for exactly that reason, and
  the wire format should not quietly undo it. (Corrected in the plan at
  `1f1a5c9`; this note had inherited the earlier wording.)
- **Security Boundary**: `DecisionRequest` explicitly excludes `posting_authority`, `approval_id`, `status`, or `entry_id`. With `extra="forbid"`, clients cannot tamper with ledger authority fields over HTTP.

## 6. Open Questions (spec §8) — carried forward, not resolved

1. **No concurrency limit on batch threads.** Two simultaneous uploads run two
   batches sharing one free-tier quota. M5-B measured **266 rate-limited calls**
   for a single 30-invoice batch at `max_concurrency=4`, so quota — not
   concurrency — is already the binding constraint. A limit here would be
   guessing at a number; M6's cost cap (item 6.6) is where it belongs.
2. **Spooled uploads have no retention policy.** Files accumulate under
   `upload_dir`. Deleting them after a batch would break any re-run that
   resolves `invoices.source_path`; keeping them forever is what happens today.
3. **SSE has no `Last-Event-ID` resumption.** A dropped client loses progress but
   never the batch, because `GET /batches/{id}` counts rows. Adding resumption
   means persisting progress, which contradicts §2.4's decision that it is
   ephemeral.
4. **`/health` does not check the LangGraph checkpointer.** It pings the `app`
   schema only. A broken `langgraph` schema would report healthy until the first
   approval thread failed — and approvals are the one thing that must survive a
   restart.
5. **`invoices.status` still has no state machine** (inherited from M5-A §8.3 and
   M5-B). Nothing prevents `posted → validated`. M5-C adds no direct writer, but
   it does add readers that now display the field to a human.

### Answered by this milestone

- **Does the department field belong on the upload?** Yes, optional — §3 above.
  Its absence is recorded as a consequence rather than defaulted away, following
  M4-D's removal of the invented budget limit.
